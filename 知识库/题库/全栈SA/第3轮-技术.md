# Round 3 · 技术深度面（交叉面）

> **目的**：验证 JD 要求的"AI 落地实践能力（数据处理/RAG/微调/推理优化）+ 云架构功底 + 动手能力"。
> **面试官**：产研专家 / 技术大牛交叉面。他不关心你怎么卖，关心你**是不是真懂**——会拿你简历上的项目往死里追问。
> **时长**：60 分钟。**策略**：用真实项目（如 RAG/Agent 经历）打底，不会的坦诚说不会 + 给补法，别硬编。

## 面试官画像

写代码出身的技术专家，最擅长"顺着你说的往下挖三层"。你说 RAG，他问 chunking；你说 chunking，他问 overlap 和语义切分；你说 embedding，他问选型和维度。
**他在测你的知识边界在哪、边界之外是诚实还是编造。**

## 题目

### Q1 讲讲你做的 RAG 项目（结合 ResolveAgent/知识库经历）：全链路怎么设计的？
**追问**："chunking 怎么切的？overlap 多少？为什么？"
**参考要点**：能讲完整链路（清洗 → 切分 → 向量化 → 检索 → rerank → 生成 → eval），每步有取舍依据。切分讲"按语义边界而非固定长度"、保留元数据。
**红线**：只会调 API 说不出链路；参数全靠"默认值"。

### Q2 检索效果不好，你怎么定位是召回问题还是生成问题？
**追问**："recall@k 和命中率你怎么测？有 golden dataset 吗？"
**参考要点**：分层归因——先单独评估检索（召回率/命中率），再评估生成（忠实度/相关性）；用标注集隔离变量。体现"eval 驱动"而非凭感觉。
**红线**：效果不好就"换个更大的模型"。

### Q3 embedding 模型怎么选？中文场景、领域术语多，你怎么处理？
**追问**："要不要微调 embedding？向量维度高低有什么影响？"
**参考要点**：选型看中文支持/维度/成本/是否可私有化；领域术语可加同义词扩展或微调；维度影响存储与检索精度的 trade-off。
**红线**：说不出任何具体模型/选型维度。

### Q4 大模型推理优化你了解哪些？（vLLM / 量化 / PD 分离 / KV cache）
**追问**："vLLM 为什么快？PagedAttention 解决什么问题？"
**参考要点**：能讲 continuous batching、PagedAttention（显存碎片）、量化（精度换吞吐）、PD 分离（prefill/decode 资源特征不同）。这是 SA 岗 AI 算力的硬通货，务必补强。
**红线**：完全没概念（这是本岗位明确要求的项，不会要坦诚 + 给学习计划）。

### Q5 客户要做模型微调，你评估要不要做的依据是什么？SFT / LoRA / 全参的区别和成本？
**追问**："LoRA 为什么省显存？多少数据够微调？"
**参考要点**：先 RAG 后微调的判断；LoRA = 低秩旁路、冻结主干省显存；数据量级与过拟合风险；微调后的评测闭环。
**红线**：把微调和 RAG 混为一谈；说不出成本差异。

### Q6 现场设计题：给 20 万条历史工单做自动分类 + 相似工单推荐，你怎么设计？说数据流和关键技术点。
**追问**："分类标签体系怎么定？新出现的故障类型怎么办？"
**参考要点**：数据清洗 → 标签体系（层级分类）→ 分类模型/LLM 打标 → 相似推荐（向量近邻）→ 人工抽检校准 → 冷启动与增量更新。讲清工程闭环。
**红线**：只说"用大模型分类"没有数据流和评估。

### Q7 云架构功底：K8s 里一个 Pod 起不来，你的排查思路？（SRE 背景送分题，别丢）
**追问**："ImagePullBackOff 和 CrashLoopBackOff 分别怎么查？"
**参考要点**：describe → events → 分层（调度/镜像/运行时/探针/资源）→ 日志定位。体现系统化排查而非瞎试。
**红线**：SRE 出身却答不利索（会被质疑简历真实性）。

### Q8 多租户/客户数据隔离怎么设计？（专有云里多个工厂共用一套 AI 平台）
**追问**："向量库怎么做租户隔离？模型会不会串数据？"
**参考要点**：逻辑隔离（租户 ID + 权限）vs 物理隔离；向量库按 namespace/collection 隔离；推理侧无状态、上下文不跨租户；审计日志。
**红线**：没考虑过隔离，或只会说"加个权限"。

### Q9 你怎么评估一个 AI 方案上线后的真实效果？（不是 demo 效果）
**追问**："线上效果衰减了怎么办？"
**参考要点**：业务指标（采纳率/解决率/MTTR）+ 模型指标（准确率/幻觉率）+ 持续监控与回流（badcase 收集 → 迭代）。体现"上线才是开始"。
**红线**：只看 demo 跑得通。

### Q10 你技术栈里最弱的一环是什么？（如 GPU 推理栈/大数据）你打算怎么补？
**参考要点**：坦诚 + 具体计划（如"推理优化我了解原理但缺千卡实战，计划通过 X 方式补"）。高管和压力面都会再问这题，答案要一致。
**红线**：说"我没有短板"；短板跟岗位强相关却毫无补救计划。

## 本轮通过标准

- RAG 全链路讲得清、每步有取舍、用 eval 说话
- 推理优化/微调有真实理解（弱项坦诚 + 有计划，不硬编）
- 云架构/SRE 基本功扎实（这是你的差异化护城河）
- 知识边界清晰：边界内深、边界外诚实
