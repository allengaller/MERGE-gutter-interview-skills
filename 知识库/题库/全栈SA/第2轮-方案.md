# Round 2 · 业务方案面（核心轮）

> **目的**：考察 JD 最核心的"客户需求洞察 + 云&AI 全栈方案设计 + POC + 差异化赢单"。
> **面试官**：资深 SA / 你的直属领导。他会用一个真实客户场景压你，看你有没有"顾问思维"。
> **时长**：60 分钟。**这是决定生死的一轮**——方案设计能力不过，后面都免谈。

## 面试官画像

干了 8 年 SA 的老兵，最烦两种人：① 上来就背产品参数的"人肉官网"；② 只谈技术不谈钱的"工程师"。
他要看到的是：**先问清需求 → 再给方案 → 方案能算账 → 讲得出差异化 → POC 有量化标准**。

## 贯穿场景（Round 2/3/4 共用，保持回答一致）

> **某头部制造业集团**（年产值 500 亿，设备故障工单历史 20 万+ 条，3 万种设备型号，IT 团队 200 人）：
> - 痛点：① 设备诊断依赖老师傅经验，知识没沉淀；② IT 服务台 30% 工单重复；③ 故障平均响应 4 小时。
> - 诉求：建"设备故障智能诊断 + 知识问答助手"。
> - 约束：CIO 要求 **6 个月见效**、预算有限、**数据不能出集团**（合规红线）。
> - 你作为阿里云 SA 去谈这个客户。

## 题目

### Q1 第一次见客户 IT 负责人，你开口先问哪 5 个问题？按优先级排序并说明理由。
**追问**："为什么不先问技术现状？"
**参考要点**：分层提问——业务目标（成功指标）→ 现状 → 数据可得性 → 组织/决策链 → 约束（合规/预算/时间）。先业务后技术，先目标后手段。
**红线**：开口就问"你们服务器什么配置"；问题无逻辑堆砌。

### Q2 客户说"我要上大模型"，你怎么判断他是真痛点、跟风、还是想换系统？怎么把"要 AI"翻译成业务成功指标？
**追问**："如果他其实只是想要一个新 ITSM 系统呢？"
**参考要点**：用"如果成功了，3 个月后你希望看到什么变化"倒推真实诉求；把 AI 翻译成 MTTR、重复工单占比、人效等可量化指标。敢指出"你可能不需要大模型"。
**红线**：客户说啥就做啥，不辨别。

### Q3 给出端到端架构（数据接入 → 知识构建 → 模型 → 应用 → 安全合规），画出来并说明主链路和失败路径。
**追问**："检索不到答案怎么办？模型幻觉怎么防？"
**参考要点**：五层架构 + 混合检索（设备型号走关键词、语义走向量）+ 答案带引用 + 失败路径降级为"未命中标记 + 转人工"（绝不瞎答）。
**红线**：只画理想链路，没有失败路径和降级。

### Q4 产品选型：这个场景用阿里云哪些产品？（ECS/RDS/OSS/SLB/PAI/百炼/通义/专有云）说清每个的边界和为什么选它。
**追问**："为什么不用 XXX（另一个阿里云产品 / 开源）？"
**参考要点**：能讲清七大件 + AI 全栈的适用场景与边界；选型有取舍依据，不是堆产品。
**红线**：产品堆砌说不出边界；七大件说不全。

### Q5 数据不能出集团是硬约束——公有云、专有云、混合云三种方案你怎么设计？各自代价是什么？
**追问**："混合云的数据同步和安全边界怎么保证？"
**参考要点**：明确本场景倾向专有云/私有化（合规优先），但讲清代价（成本、运维、模型更新）；给混合云时的边界设计。体现"合规 > 便利"的判断力。
**红线**：忽略合规约束硬推公有云。

### Q6 模型选型：通义开源版私有化部署 vs 百炼 API vs 微调，决策依据是什么？什么情况下必须微调？
**追问**："微调要多少数据？客户有吗？"
**参考要点**：默认 RAG + 开源模型私有化；微调仅在"领域术语极强/格式强约束/开源模型效果天花板"时上；评估数据量与成本。
**红线**：张口就要微调（最贵最慢）；说不清三者边界。

### Q7 估算规模：知识助手注册用户 1 万、日活 2000、日均问答 5 万次、高峰并发约 500——算力/存储/带宽怎么估？给量级。
**追问**："推理用几张卡？怎么算的？" / "如果 CIO 拍脑袋说要支持 2 万并发呢？"
**参考要点**：能给出量级估算（峰值 QPS × 平均 token → 吞吐 → 卡数；知识库 20 万文档 → chunk 数 → 向量存储），讲清假设。估算题重在"思路可复现"，不在精确；面试官给出不合理数字时，敢质疑前提（"2 万并发跟内部服务台量级不匹配，我们先对齐口径"）是加分项。
**红线**：张口就来没过程；完全不敢估。

### Q8 给 CIO 算 ROI：方案投入 vs 省的钱，你用什么口径算？客户说"太贵"你怎么应对？
**追问**："省的钱怎么量化，CIO 凭什么信你？"
**参考要点**：三本账——人力（重复工单减少）、效率（MTTR 下降）、损失（停产/故障减少）；给保守口径 + 对标案例。"太贵"时拆 TCO、分期、先 POC 降本验证。
**红线**：只谈技术价值不谈钱；算不出账。

### Q9 客户算法团队说"我们用开源模型 + K8s 自己搭就行，为什么买你们的？"怎么回答？
**追问**："如果他们坚持自研呢？"
**参考要点**：先肯定 → 算 TCO（人力/踩坑/运维）→ 讲时效（6 个月窗口）→ 讲差异化（合规/评测体系/行业 Know-how）→ 留口子（自研也卖算力底座）。不硬刚。
**红线**：贬低客户能力；只说"我们更好"说不出为什么。

### Q10 POC 策略：目标、范围、成功标准（量化）、周期、风险预案分别是什么？POC 结果不好怎么办？
**追问**："对 POC 结果负责，具体怎么负责？"
**参考要点**：验证业务指标改善而非"AI 能力"；范围克制（1 工厂 1 场景）；成功标准量化 + 双方签字；结果不好先定位数据/模型/场景问题，给替代路径。"负责 = 保证结论可信"。技术建议按 JD 的五维框架给：**安全性**（数据不出域/权限）、**稳定性**（降级兜底）、**性能**（响应延迟）、**可持续性**（模型与知识的更新机制）、**运行效率**（人力投入）——这五维是给客户做技术建议的标准口径。
**红线**：成功标准是"跑通就行"；没有结果不好的预案。

### Q11 6 个月落地路线图：分几阶段？每阶段里程碑、验收标准、风险点？
**追问**："第 3 个月数据接入延期了怎么办？"
**参考要点**：POC 验证 → 单厂上线 → 全集团推广三段；每段有量化验收；预留 buffer；识别关键依赖（数据、人力、客户配合）。
**红线**：路线图无里程碑/无风险点。

### Q12 这个项目走公开招标：你怎么制定招投标策略？技术标怎么写才能拿高分？
**追问**："友商商务标报价低 20%，你怎么应对？"
**参考要点**：
- 投标策略：先吃透评标规则（技术分/商务分/权重）→ 识别得分点与失分点 → 判断是"引导标书"（把我们的差异化写进技术要求）还是"响应标书"
- 技术标三关键：逐条应答不遗漏、方案差异化（专有云合规/评测体系/行业 Know-how）、交付承诺量化（里程碑/验收标准）
- 模板沉淀：细分领域通用技术架构方案 + 应答矩阵，对应 JD"撰写通用招投标材料或汇报模版"
- 应对低价：打 TCO（运维/返工/人力成本），不打裸价格战
**红线**：逐条应答有遗漏；友商低价就跟风降价。

### Q13 向客户高层演示时，怎么用标杆案例 + 场景化演示打动他们？演示要准备什么？现场失败怎么办？
**追问**："没有同行业标杆案例怎么办？"
**参考要点**：
- 演示设计：不演功能，演"客户自己的场景"——拿客户真实工单样本（脱敏 + 合规授权）跑一遍诊断，让 CIO 看到自己的数据被解决
- 标杆案例：选同行业/相似规模/有量化结果的（MTTR 降 X%），最好能安排客户互访背书
- 双保险：主演示录屏备份 + 截图兜底，不依赖现场网络
- 现场失败：切备份录屏，坦承原因并承诺复测——绝不硬撑掩饰
**红线**：演示脱离客户场景；没有任何备份预案。

## 本轮通过标准

- 先问需求再给方案（顾问思维），方案能算商业账
- 架构有主链路 + 失败路径，产品选型讲得清边界
- 差异化讲得出"为什么是阿里云"，POC 有量化标准
- 全程把客户合规约束（数据不出集团）当作设计前提而非事后补丁
