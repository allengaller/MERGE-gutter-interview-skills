## 一、Agent 工程

### 01 ｜ resolve-agent —— 生产级产品支持智能体平台

**一句话**：告警进来，处置出去——把「告警 → 根因定位 → 修复执行」的完整响应链路端到端自动化。

- **智能路由**：接收客户多模态输入，按故障特征在 **FTA 故障树 / WIKI 知识库 / 技能 / 代码分析**四条路径间分发
- **闭环收敛**：基于 **AgentScope**、以 Loop 工程思路组织响应链路，把诊断与处置收敛在同一平台
- **双端交付**：**WebUI + Mac App**（在研）

**硬指标**：**432 个场景** ｜ **23 项** Agent 定制功能
**对比**：告警聚合工具只解决「看见了」，单点问答工具只解决「说到了」——它把问题「修掉了」。

### 02 ｜ agent-up —— Agent 配置全生命周期管理（AgentOps）

**一句话**：让 Agent 配置变更像代码发布一样可控——审批发布、效果追踪、一键回滚。

- **AI 归因**：用户反馈经 AI 归因自动转化为配置变更建议，上线后自动生成效果报告
- **可撤销**：四分区编辑器支持**分区级回滚**；变更全程**可审计、可撤销**
- **闭环**：编辑 → 审批发布 → 效果追踪 → 回滚，完整生命周期一个平台

**硬指标**：**232 个**自动化测试 ｜ **30 个** API
**对比**：直接手改配置没有后悔药；这里有审批、有追踪、有一键回滚。

### 03 ｜ docsy —— 面向 Agent 时代的文档平台

**一句话**：文档不止给人看——把普通 Markdown 重构为机器可解析、可校验、可执行的研究包。

- **质量可量化**：**14 条** Linter 规则 + **0-100 健康评分**，每篇文档自带体检报告
- **规模验证**：实测稳定支撑 **21,000 篇**文档的大仓库
- **工程纪律**：**175 个**自动化测试，覆盖率 **81%**

**对比**：静态文档站只对人负责；这里的文档能被 AI 直接消费和验证。

### 04 ｜ mcp-database —— 自托管 MCP Server 统一框架（mcp4coder）

**一句话**：把散装 MCP 接入收敛成一套基类——新增一个 Server 只需实现两个方法。

- **规模收敛**：**37 个 Server、200+ 工具**统一进一套基类
- **边际成本**：接入成本从**周级降到小时级**
- **安全默认**：内置 **JWT 双认证**与沙箱隔离

**对比**：逐个散装接入 MCP 每次都在重复造轮子；一次收敛，长期复利。

### 05 ｜ sokr —— 运维团队 OKR 与复盘沉淀工具

**一句话**：复盘不是开完就散——把故障复盘直接沉淀为可毕业的团队技能资产。

- **六层链路**：目标 → 关键结果 → 专项 → 课题 → 工单 → 技能，复盘经验有出口
- **零门槛**：纯浏览器运行，**零部署**
- **工程纪律**：**330 个**自动化测试

**对比**：常规 OKR 工具只管目标对齐；这里复盘经验直接变成可复用技能。

### 06 ｜ skills-database —— 职业技能与 Skills 技能融合平台

**一句话**：455 条岗位胜任力技能，人与 Agent 共用的能力地图。

- **覆盖**：**455 条**技能 × **27 个**职业角色
- **数据纪律**：每条来源可溯、分类可**幂等重建**
- **可用性**：单文件即可离线浏览

**对比**：大而全的技能清单看过就忘；这里每条技能都为胜任力服务。

## 二、AI Infra 与云原生

### 07 ｜ kudig-database —— K8s 与 AI Infra 生产运维全域知识库

**一句话**：故障诊断的底座语料——4,750 篇文档加一台故障树引擎，人与 Agent 双读。

- **规模**：**4,750 篇**文档 · **21 个**技术域 · **13 家**云厂商
- **故障树引擎**：**16 个**顶层事件、约 **300 个**底事件——诊断路径可枚举、可评测
- **双读设计**：可直接作为 **LLM-Wiki 语料**接入智能体

**对比**：人读为主的文档站到 Agent 手里就失效；它生来就是智能体语料。

### 08 ｜ ai-guru-database —— 中文 AI 全栈开源知识库

**一句话**：从数学基础一路讲到 Agent 生产部署的完整体系。

- **规模**：**2,061 篇**核心文档 · 约 **1,894 万字** · **700+ 张**概念卡
- **体系**：**24 章**完整知识体系 + **三层阅读路径**，不同背景读者各有入口

**对比**：碎片化教程合集学完即忘；这里体系完整、路径清晰。

### 09 ｜ klaw —— 单二进制 K8s 智能运维平台

**一句话**：一个文件装下一支夜间值班队伍——控制台、诊断、ChatOps、告警、SOS 语音五合一。

- **五合一**：控制台 / 诊断引擎 / ChatOps 机器人 / 实时告警 / SOS 语音，**单二进制**交付
- **诊断深度**：**9 大类 73 个**分析器，事件推送延迟 **< 1 秒**
- **效率证据**：排障过程 API 调用**下降约 90%**

**对比**：Dashboard + 机器人 + CLI 的多工具拼装 vs 一个二进制——夜间值班尤其受益。

### 10 ｜ etcd-guardian —— etcd 备份恢复 Kubernetes Operator

**一句话**：补上 Velero 在托管集群里摸不到 etcd 数据面的盲区。

- **原生接口**：直调 etcd 原生快照与恢复，保证 **revision 一致性**与**成员重建顺序**
- **大库支持**：**10GB+**；对阿里云 **ACK 用户开箱即用**
- **生态整合**：可作为 module 接入 klaw

**对比**：托管集群的 etcd 备份是公认盲区；这是专用解，不是通用工具的勉强凑合。

### 11 ｜ kubernetes-network-master —— K8s 网络排障 kubectl 插件

**一句话**：把 K8s 网络排障收敛为一条命令——逐跳因果链追踪，自动标记断点。

- **逐跳追踪**：DNS → 网络策略 → Service → TCP → MTU → CNI，断点自动标记
- **零侵入**：kubectl 插件形态，集群内**无需安装任何组件**；**20+** 子命令
- **技术纵深**：内含 **CNI 无关的轻量 eBPF**

**对比**：进容器手敲命令的传统排障 vs 一条命令定位断点。

## 三、TAM / SRE 领域

### 12 ｜ open-tam —— 基于 AgentScope 与 MCP 的多 Agent 排障系统

**一句话**：排查即语料——每排一次故障，都在为下一代智能体积累资产。

- **三段式报告**：告警进来，输出**现象 / 根因 / 处置建议**
- **trace 全落盘**：每一步思考、工具调用、观察可回放——新人照 trace 就能学会老专家的排查路径
- **评测内置**：故障注册表同时就是**评测集**；仿真 mock 与实盘切换**零改动**

**对比**：黑盒排障工具只给答案；它把排查过程本身变成可复用的资产。

### 13 ｜ kuba-database —— 全网重大生产故障复盘数据库

**一句话**：94 个 P0-1 级真实故障、46 年跨度的结构化复盘库——别人的事故，你的经验。

- **规模**：**94 个 P0-1 案例** · **46 年**跨度 · **47 家**公司 · **12 类**根因
- **多视角拆解**：SRE / CRE / FDE 等多角色视角，补全根因、影响、证据、对策完整链条
- **工程化**：全库纯 Markdown + 版本管理，可追溯、可定量统计

**对比**：零散事故报告合集 vs 可检索、可统计的结构化资产。

### 14 ｜ cmd-database —— 命令行语料数据库

**一句话**：1,100+ 个命令的生产级说明书——既是人的速查手册，也是 Agent 的工具知识。

- **规模**：**1,100+ 命令**各建一页 · **741 篇**生产最佳实践（语义内涵 / 生产实践 / 风险提示）
- **单一来源**：YAML → 双向链接文档 → **Go CLI** 检索校验，三层始终一致

**对比**：命令速查表只告诉你「怎么敲」；它告诉你「什么时候该敲、敲错了会怎样」。

## 四、交付工程与跨学科知识工程

### 15 ｜ fde-scope —— FDE 现场操作系统

**一句话**：把交付质量写进门禁里——资格预审到客户交接的全流程软件化。

- **流程固化**：**4 阶段 · 18 环节 · 10 道代码级门禁**，其中 **7 道**源自 FAT、ISO 13849、CE 等工业标准
- **全闭环**：交付之后的**运维化**也纳入闭环

**对比**：同类工具只覆盖交付环节；它管到客户交接后的运维化。

### 16 ｜ repo-database —— 面向 FDE 的优质仓库兵器库

**一句话**：每月扫描 1,000+ 仓库——机器聚合管广度，人工策展管深度。

- **规模**：每月 **1,000+ 仓库**扫描 · 精选 **115 篇**结构化档案 · **10 个**技术领域
- **质量门禁**：六节结构化写作 + CI 门禁校验；**100 个**自动化测试守护数据一致性

**对比**：纯爬虫榜单给数量；这里每篇档案都过了门禁。

### 17 ｜ mechanic-romance —— 具身智能研究语料库

**一句话**：把论文、代码、笔记三座孤岛统一到同一套场景模板与引用规范下。

- **覆盖**：**10 篇**方法笔记 · **22 种**硬件 · **6 个**仿真环境 · **8 个**演示场景
- **可信度门禁**：待核实状态明示标注，不装权威

**对比**：区别于晒进度的内容农场——研究笔记也可以有引用规范。

### 18 ｜ open-cognition-database —— 跨学科认知知识库

**一句话**：专为 Agent 消费设计的认知知识库——137 个标准化 Skill 可被大模型直接挂载。

- **规模**：**9 大领域 · 2,400+ 条目 · 1,075 位思想家 · 1,112 个概念**
- **Agent 优先**：条目以约百行紧凑写法组织；**137 个**标准化 Skill 直接挂载

**对比**：人读百科的信息密度对 Agent 不友好；它从写法上就是为挂载设计的。

### 19 ｜ peace-lab-database —— 身心疗愈智能体中文知识库

**一句话**：疗愈类智能体的合规语料底座——每个技能都内置医疗转介红线。

- **规模**：**4,900+ 篇**文档，六大支柱 + 跨域聚合层，整库可直接挂载为 WIKI 语料
- **合规设计**：**24 个** Agent Skills 全部内置**医疗转介红线**

**对比**：普通疗愈内容合集 vs 为疗愈类智能体设计的合规底座。

### 20 ｜ oran-database —— O-RAN / AI-RAN 专家知识库

**一句话**：给具身智能工程师的 5G/6G 通信知识库——附一条可执行的转型路径。

- **覆盖**：**35 个**知识目录 · RIC 与 xApp 开发 · **2026 AI-RAN** 前沿 · **11 家**厂商档案
- **转型路径**：云技能 → O-RAN 能力映射，**6 阶段 · 14-20 周**完成过渡

**对比**：直接堆 3GPP 规范劝退所有人；它把规范翻译成工程师的成长路径。
