# 岗位适配评估

> **用途**：基于 `SA匿名.md`（口径基准）评估目标岗位适配度，决定投递优先级与简历改写方向。
> **纪律**：评估中的每条「证据」都必须能回溯到简历真实数字，面试可交叉验证；不匹配就明说不匹配。

## 一、通用岗位适配评估

基于素材（研发底子 + 11 年阿里云客户一线 + 智能体 0→1 + 知识产品化能力）：

| 岗位 | 适配度 | 理由 / 差距 |
|---|---|---|
| AI Agent 产品经理（ToB） | 高 | 智能体平台本身就是产品实践：场景覆盖率 80%、托管成功率 40% 就是北极星指标；10 年工单/故障经历 = 需求洞察来源。**最接近 PM 的路径** |
| 技术产品经理（云产品 / AIOps / 可观测） | 高 | klaw、etcd-guardian、open-demo 都是"产品思维"的开源证明，且懂一线痛点 |
| 客户成功负责人（AI/SaaS 大客户） | 高 | 与 TAM 高度同构，海外 AI 公司常招这类"技术型 CSM" |
| SRE/稳定性负责人（团队向） | 中高 | MTTR、闭环率、人效全是 SRE 语言；差距在带团队规模偏小（专家组 IC-lead） |
| DevRel / 技术布道师 | 中高 | 4 本书 + 22 仓库 + 959 案例 = 天然内容机器；差距是偏内向深耕而非舞台型 |
| 交付/项目经理 | 中 | 交付经验足，但偏技术判断而非项目群管理 |
| 经典产品经理（C 端/增长/商业化） | 低 | 简历上没有收入、留存、增长口径的证据 |

**PM 方向判断**：能做，但只限「技术型 PM / AI 产品经理」窄门。简历需换骨：从"专家/架构师语言"改为"问题定义 → 方案取舍 → 上线指标 → 迭代闭环"的产品语言，把智能体平台与核心开源重新包装为"独立产品：定位、用户、指标"。**最大短板是商业化证据缺失**（无签单额、续约率、定价参与类数字），TAM 交付价值经历只能间接支撑。

**优先级**：AI Agent PM（真实差异化，市场缺懂工单场景的人）> 技术型云产品 PM > 其他。

已有简历版本：SA（`SA.md` / `SA匿名.md`）、FDE（`FDE.md`）、TAM（`TAM.md`）、大模型训练 SRE（`LLM-SRE.md`）、Argo TAM（`Argo-TAM.md`，真实信息版，强化 AI Stack / Agent 工程 / 学术 / 开源，已清理 SA 内容）。

## 二、专项评估：大模型训练生产 SRE 高阶岗（深圳/上海/北京）

### JD 解读

三条职责本质是三个角色拼图：

1. **训练链路稳定性治理** → 值班长/SRE 侧：oncall、应急、稳定性方法论
2. **诊断/可视化/自愈系统建设** → AIOps 平台建设者：跨框架/算力/网络/存储的基础设施协同
3. **训练生产 oncall、排障、流程优化** → 值班长体系 + 流程工程

两条硬性技术栈要求：大模型训练流程与框架原理；GPU/NCCL/CUDA/RDMA 调优。

### 匹配矩阵

| JD 条目 | 我的证据 | 判定 |
|---|---|---|
| 职责 1：训练链路稳定性治理 | 应急值班长 2 年：MTTR ↓20%，重保零重大故障；专家组闭环率 90% | 强匹配（方法论完全同构，缺训练场景特化） |
| 职责 2：诊断/可视化/自愈建设 | 运维智能体平台 RAG→ReAct、FTA 故障树引擎（16 顶层事件/约 300 底事件）、klaw 73 个分析器、知识图谱/LLM-Wiki | **强匹配（本岗最大亮点）** |
| 职责 3：oncall/排障/流程建设 | 值班长体系就是 oncall/升级/流程建设的教科书；割接与重保方法论已复制推广全区域 | 强匹配 |
| 要求 1：预训练/后训练流程 + Megatron/PyTorch 原理 | 《大模型入门与实战》42 万字 + 《大模型全栈实战指南》106 万字（算法底座→工程落地）、ai-guru-database 约 1,894 万字知识体系；但**无生产训练任务运维经验** | 理论可讲、实战缺失 |
| 要求 2a：k8s/docker 容器原理 | ACK 容器技术专家组组长 3 年，三条产品线疑难工单闭环率 90%；kubernetes-network-master、etcd-guardian、klaw | **满分** |
| 要求 2b：GPU/NCCL/CUDA/RDMA 调优 | 无生产证据。间接迁移：嵌入式驱动适配背景（MicroTCA VCU 卡）、存储线 PE、网络逐跳因果链排障功底（RDMA 属网络域）、AI Stack 工单一手场景 | **缺失，最大硬伤** |
| 要求 3：大规模任务系统故障排查 | 专有云大规模集群疑难处置；AI Stack 智能体冷启动两周后一周 50 单、闭环率 95%（AI 基础设施工单场景） | 部分匹配（非训练任务，但属 AI Infra） |
| 要求 4：责任心/自驱/沟通 | 值班长 + TAM 本身就是该素质的岗位化证明 | 强匹配 |

### 结论

**综合适配约 65-70%，值得投，但要按"迁移叙事"打，不能按"对口"打。**

- 三条职责（稳定性治理、自愈平台建设、oncall/流程）全部强匹配——这恰恰是训练 SRE 团队最难招到的部分；缺口集中在 GPU/NCCL/Megatron 技术栈，属于可 3-6 个月补齐的类型。
- **风险**：高阶岗通常以训练集群实战为隐性门槛，第一轮技术面可能被 GPU 细节（NCCL 超时定位、掉卡、checkpoint 恢复）问穿。
- **核心叙事牌**：AI Stack 冷启动两周 → 一周 50 单闭环率 95%，就是"快速进入全新 AI Infra 领域"的最硬学习速度证据，直接回答"你怎么补训练领域 gap"。
- **定位话术**：不吹训练经验。定位为「云原生 SRE + 应急指挥专家 + AIOps 平台建设者，向大模型训练场景做第三次迁移」——此前 TAM→值班长→专家组两次转型都是成功的先例。

### 面试前补课清单（按优先级）

1. NCCL 集合通信原理与超时/ hang 排查（NCCL_DEBUG、拓扑感知、ring/tree 算法）
2. GPU 故障模式与处置：掉卡、ECC 错误、XID 错误码、NVLink/PCIe 拓扑、MIG
3. RDMA/RoCE 无损网络：PFC/ECN、常见抖动导致的 slow node 定位
4. Megatron 并行策略（TP/PP/DP/EP）与 checkpoint 机制、断点续训
5. 训练可观测指标：loss spike、grad norm、MFU/TFLOPs 利用率、straggler 检测
6. 训练自愈模式：任务级重试、节点隔离、rank 级重启、弹性调度
