# Interview Coach — 通用面试教练

> Gutter v2 · 对话式面试练习 + 运维快答 · Skill + 知识库 双形态

> **职责划分（2026-09-23 更新）**
> - **本仓库 = skill 主仓**：`interview-coach` + `k8s-ops-quick-qa` + `llm-ops-quick-qa` 三个技能，以及它们自带的自包含题库（各 skill 的 `卡/`）。**技能继续在这里改。**
> - **求职内容定稿在 [oh-my-career](https://github.com/allengaller/oh-my-career)**：简历（`docs/10~12-简历-*`）、画像（`docs/33-背景画像/`）、题库（`docs/31-面试题库/`）、主题（`docs/32-面试主题/`）。那边的文件按 `NN-角色-级别.md` 重命名过。
> - 本仓库 `知识库/` 是这些内容的**工作副本**（skill 按 `知识库/…` 相对路径引用它）。**两边同名文件改动必须双向同步**，否则会漂。
>
> **漂移已定策（不再双向同步流程）**：`oh-my-career/.qoder/skills/interview-coach/` 是 9/12–9/14 的旧副本 ——
> 缺 `流程/快问快答.md` 与 `评分/快问快答.md`，也没有两个快答 skill。要用这些能力从本仓库安装（见「安装」）。
> 那边不会补齐：它的 SKILL.md 与 README 已就地标明"旧镜像 + 主仓在本仓库"。**往两处同时写流程才是漂移的来源**，所以新流程、新卡、新示例一律只进本仓库。

## 这是什么

**三个 skill**，可以在任何能加载它们的智能体（Claude Code / Qoder / MiniMax / 任何兼容 SKILL.md 规范的 agent）里用：

| skill | 干什么 | 一句话 |
|-------|--------|--------|
| `k8s-ops-quick-qa` | K8s 运维快答 | 问完就出答案卡，不反问、不铺垫 |
| `llm-ops-quick-qa` | LLM 推理运维快答 | 同上，覆盖部署/显存/吞吐/排障/TCO/评测 |
| `interview-coach` | 对话式面试教练 | 扮演面试官、追问、评分、复盘（含快问快答） |

前两个是**快速模式**：你只想知道答案，30 秒内读完。第三个是**练习模式**：你来答，agent 只判定。
两者之间的分界见下文「路由」表。

与 v1 的区别：
- v1：PHP/Yii 站点，靠题库 + 人工阅读
- v2：**对话驱动**，agent 扮演面试官、追问、评分、给出改进建议

```
gutter-interview-skills/

│   │   ├── SKILL.md                   #     主入口（description + 触发条件）
│   │   ├── 流程/                      #     快问快答 / 系统设计 / 编码 / 行为 / 故障复盘 / SA 多轮链路
│   │   ├── 角色卡/                    #     角色卡（面试官画像）
│   │   ├── 评分/                      #     评分维度（含 快问快答.md）
│   │   ├── 示例/                      #     golden trajectory：照着走的完整会话（3 份）
│   │   ├── CONFIG.md                  #     12 个可配置开关
│   │   └── 指令/快速开始.md           #     一句话启动模板
│   ├── k8s-ops-quick-qa/              # 【快答】K8s 运维：一句话问题 → 一张答案卡
│   │   ├── SKILL.md
│   │   └── 卡/                        #     自包含题库（负载/网络/控制面/节点存储/变更运维/可观测性与SLO/数字弹药）
│   └── llm-ops-quick-qa/              # 【快答】LLM 推理运维：同上，引擎/显存/吞吐/故障/TCO/评测
│       ├── SKILL.md
│       └── 卡/                        #     自包含题库 + 数字弹药.md
├── 知识库/                            # 知识库形态：给人/agent 直接读
│   ├── 画像/                          #   按角色：用户背景画像 + 项目经验 + 技能树
│   ├── 主题/                          #   按主题：可复用的知识块
│   ├── 题库/                          #   按角色分级的面试题库
│   └── 简历/                          #   简历：模板 + 项目经历写法
├── archive/                           # v1 历史归档（git 保留）
└── README.md                          # 你正在读
```

**两个形态互为表里**：
- Skill 是入口 — agent 加载 SKILL.md 后知道"什么时候触发、怎么扮演面试官"
- 知识库是弹药 — 按需被 skill 引用，给 agent 喂上下文和题库

> **为什么两个快答 skill 的题库放在 skill 里（`卡/`）而不是 `知识库/`**：
> skill 会被链接到 `~/.qoder/skills/` 全局加载，从那里出走的 `../../../知识库/` 落在仓库外读不到。
> `卡/` 与 SKILL.md 同级，跟着 symlink 一起走，**装完即可用**。

## 安装

装到 `~/.qoder/skills/`，任意目录都能调起。**三个必须一起装** —— interview-coach 的快问快答会引用兄弟 skill 的 `卡/`，只装一个会出现半条断链。

```bash
mkdir -p ~/.qoder/skills
R=/Users/allengaller/Documents/GitHub/allengaller/gutter-interview-skills/.claude/skills
ln -sfn "$R/k8s-ops-quick-qa" ~/.qoder/skills/k8s-ops-quick-qa
ln -sfn "$R/llm-ops-quick-qa" ~/.qoder/skills/llm-ops-quick-qa
ln -sfn "$R/interview-coach"  ~/.qoder/skills/interview-coach
```

验证（三行都应打出 `SKILL.md`）：

```bash
ls ~/.qoder/skills/{k8s-ops-quick-qa,llm-ops-quick-qa,interview-coach}/SKILL.md
```

不支持 symlink 的环境改用复制：`cp -R "$R/k8s-ops-quick-qa" ~/.qoder/skills/`（复制后更新要重跑，symlink 是即时生效的）。

> **装完必须重启会话**，`/k8s-ops-quick-qa` 才会出现在技能列表里。skill 列表在会话启动时扫描，运行中新建的链接不会被发现。

## 使用方式

### 用法 A · 快速模式（要答案，零仪式）

**什么都不用写**，直接问：

```
Pod 一直 Pending，kubectl describe 没事件，下一步看什么？
8×H20 部署 320B MoE，TP 给多少，一句话
```

- 不加载 interview-coach、不反问角色/年限、不说"好的，我来为你解答"
- 输出**一张答案卡**（≤200 字）：`一句话 → 30 秒答 → 弹药 → 红线 → 下一问`
- 同一条消息里带开关改行为：`短` / `深` / `一句话` / `分类 显存`

### 用法 B · 快问快答（我答题，你只判定）

```
SRE 快问快答 10 道
```

走 `interview-coach/流程/快问快答.md`：出题 ≤25 字，判定三档（✅ 过 / ⚠️ 半 / ❌ 挂）≤60 字，追问层级默认 0，agent **不作答**。收尾一行：`{对}/{总} ｜ 最弱：{一类} → 刷 卡/{文件}.md`。

### 用法 C · 完整模拟面试

```bash
"按 interview-coach skill 给我来一轮系统设计面试，云原生 SRE 岗，3 年经验"
```

agent 会自动：
1. 读取 `.claude/skills/interview-coach/SKILL.md`
2. 按 `角色卡/云原生SRE.md` 配置面试官
3. 按 `流程/系统设计.md` 推进流程
4. 按 `评分/系统设计.md` 评估回答

### 用法 D · 直接当知识库读

```bash
cat 知识库/题库/云原生SRE/高级.md   # 浏览题库
cat 知识库/画像/云原生SRE/画像.md   # 看角色画像
```

## 路由：哪句话走哪个 skill

| 你说的 | 走的 | 有没有答案 |
|--------|------|-----------|
| "…怎么办 / 是什么 / 怎么查" | `k8s-ops-quick-qa` / `llm-ops-quick-qa` | ✅ 给答案卡 |
| "考我 / 抽问 / 连问 / 快问快答 N 道" | interview-coach `流程/快问快答.md` | ❌ 只判定 |
| "面试我 / 走一轮 / 模拟面 / 评分" | interview-coach 完整流程 | ❌ 多轮追问 + 复盘 |

> 判定口诀：**句子里有"怎么办/是什么/怎么查" = 要答案；有"考/问/抽测/模拟/我答你评" = 被考。**
> 模棱两可时按"被考"处理——出题不出答案永远不亏，反过来会破坏练习。

## 数字口径的唯一来源

两个快答 skill 各有一页 `卡/数字弹药.md`。其中 **§8「我的项目数字」两页逐字相同**（由 `scripts/check-docs.py` 在 CI 中强制；各域专属的"禁止出口"清单放在 §8 之外，允许不同）。所有 skill 判定数字时以这两页为准；口径不一致（分子/分母/测试集/时间窗说不清）直接算半对。加新数字先写这两页并同步另一页，再写题卡，不要反过来。

## 校验

```bash
python3 scripts/check-docs.py      # 0 错误即可
```

纯标准库，无依赖。检查四件事：

1. **相对路径可达**：markdown 链接与反引号里写的仓库内路径必须存在（`卡/` 这类目录泛指、以及指向 oh-my-career 的 `docs/…` 跨仓引用降级为警告）
2. **锚点有效**：`#xxx` 与 `path#xxx` 的标题锚点必须能对上
3. **声明的不变量**：两页 `卡/数字弹药.md` §8 逐字相同（见上节）
4. **意外副本**：`xxx 2.md` 形态的复制残留直接报错

`.github/workflows/docs.yml` 在改动任意 markdown 时跑它。加新不变量就往 `check-docs.py` 里加一个 `check_*` 函数，不要靠人肉记。

## 触发关键词

- **快答**（不带任何前缀即可）：「怎么查」「怎么办」「是什么」「为什么」「给个口径」
- **快问快答**：「考我」「抽问」「连问」「快问快答 N 道」「quick-fire」
- **完整面试**：「练个面试」「模拟面试」「给我来一轮面试」「按 [角色] 岗面试我」
- **题型**：「系统设计题 / 编码题 / 行为面试题 / 故障复盘」
- **SA 链路**：「走一遍 SA 多轮面试」「HR 面 / 方案面 / 技术面 / 高管面 / 压力面」
- **评分**：「评价一下我的回答」「刚那题我答得怎么样」

## 扩展指南

### 加新面试角色（三步）

1. 在 `知识库/画像/<新角色>/` 下建 `画像.md`（画像）+ `项目.md`（项目经验）+ `技能.md`（技能树）
2. 在 `知识库/题库/<新角色>/` 下按 初级/中级/高级 建题库
3. 在 `.claude/skills/interview-coach/角色卡/<新角色>.md` 建角色卡（给 agent 用的精简版），并在 `流程/快问快答.md` 的配比表里加一行

### 加新快答题卡

在对应 skill 的 `卡/<分类>.md` 里按现有格式追加。编号接在最后一题之后，**五段结构逐字照抄**：

```markdown
## {n}. {题干，≤25 字，真实故障现场形状}

**一句话**｜{结论，只说判别力最强的那一句}

**30 秒答**｜{主路径 + 判断线}。
判断线单独成句：**判断线**：{什么情况走哪条分支}

**弹药**
- {命令 / 参数名 / 指标名 / 字段路径}
- {数字，带口径}

**红线**｜❌ {最容易说错的那一条 + 为什么错}

**下一问**｜"{串联题}"（→ {一句话方向}）
```

约束：
- 数字先写进 `卡/数字弹药.md` 再引用，两页 §8 保持逐字一致
- 卡可以写满（agent 从中选题作答），但**作答输出 ≤200 字**——`弹药` 最多 4 条，其余是备用弹药
- 新分类要在该 skill 的 SKILL.md 分类表里登记，否则抽题抽不到
- `下一问` 必须能被快问快答直接出成下一题（这是两轮模式的串联入口）

详见 `知识库/索引.md` 和 `.claude/skills/interview-coach/README.md`。
