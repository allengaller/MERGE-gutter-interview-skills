SYLLABUS / 培养方案

四门必修，一门都不水。

不是题库，是完整面试流程。agent 加载 skill 后按 flow 推进：一次只问一个问题，先复述你的关键点再追问，每科追问最多三层——像真的面试官那样把你问透。

必修 · 一 系统设计system-design 从需求澄清到容量规划，追问到「为什么这么选」的层级；背图五分钟画完的，直接判背的。 45–60 分钟追问 ≤ 3 层
必修 · 二 编码面试coding 写之前先讲思路，边界条件一个个问；不替您写，最多给 30% 的提示方向。 30–45 分钟追问 ≤ 3 层
必修 · 三 行为面试behavior STAR 结构逐段拆：情境、任务、行动、结果，哪里松散追问哪里。 30 分钟可指定主题
必修 · 四 故障复盘incident-response · SRE 限定 时间线、根因、改进项——按真实 postmortem 的标准复盘你经历过的故障。 30–45 分钟SRE 角色
选修 快速问答 / 混合quick-fire · mixed 5–10 题连发，每题追问一层；或自由组合成一套 60+ 分钟的模拟考。 5–60+ 分钟按需配置
RUBRIC / 评分标准

评分不靠感觉，靠 rubric。

每场面试结束，按六个维度逐项打分、逐项给评语。不及格会直接说不及格——这是这门课唯一的温柔。

维度权重1–3 分7–10 分
需求澄清15%没问，直接画QPS / 延迟 / 一致性 / 可扩展性都问清
架构完整性25%只有主链路模块 + 数据流 + 失败路径 + 边界
关键模块深度25%选型没说为什么有 trade-off，对比 2–3 个候选
可扩展性 / 容量15%没谈具体数字 + 容量规划 + 成本估算
故障与降级10%没考虑明确的降级 / 熔断 / 限流方案
沟通与表达10%自说自话主动讨论、承认不知道、问好问题
  • 加分：主动谈 CAP 取舍、给具体数字、谈成本、指出自己设计的缺陷
  • 减分：堆技术名词不说为什么、唯一解思维、不接受追问

PROCEDURE / 考核流程

一场面试，五步闭环。

壹

问

一次只问一个问题，不连珠炮。题目来自按角色分级的真实题库。

贰

复述确认

先复述你的关键点确认理解，再决定往哪追——不误解你的回答。

叁

追问 ≤ 3 层

从「是什么」追到「为什么这么选」再到「系统性根因」，三层封顶。

肆

逐项评分

按 rubric 六个维度打分，加权总分对照 Senior / Mid 阈值。

伍

可执行反馈

亮点引用原话，改进带「下次怎么做」，并推荐 knowledge 里的练习题。

NOTICE / 开考须知

三步开考，配置随你。

  1. 把仓库克隆到任何能加载 SKILL.md 的 agent 环境（Claude Code / MiniMax / 兼容 agent）。
  2. 对 agent 说一句开考 prompt——角色、流程、严格度，一句话里指定。
  3. 答完收卷：逐项评分 + 可执行反馈 + 推荐练习，写进你的成绩单。
