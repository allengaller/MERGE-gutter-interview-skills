## 1. 两个速算公式（LLM 容量题的全部弹药都从这两条出发）

| 公式 | 用法 | 例子 |
|---|---|---|
| **权重 GB ≈ 参数量(B) × dtype 字节** | 下载前就知道要多久多久、几张卡起 | 320B BF16 → **~640GB**；72B FP16 → **~140GB**；72B W4A16 → **~36GB** |
| **KV cache ≈ 2 × 层数 × KV头数 × 头维度 × dtype字节 × 上下文长度 × 并发** | 显存天花板与并发上限 | 上下文 ×32 → KV ×32，权重不变 |

**dtype 字节**：FP32=4 / FP16=BF16=2 / FP8=1 / INT4(W4A16)=0.5。
**MoE 陷阱**：速算必须用**总参数**（320B），不是激活参数（18B）——专家全量常驻，**MoE 省算力不省显存**。

**万能句式**：说数字必须带"假设 → 公式 → 结论（区间）"。例：
> 权重 640GB、单卡 141GB → 下限 4.5 卡，所以 TP=8；但这只是地板，天花板是 KV。

## 2. 卡数推导链（唯一不许跳步的路径）

```
并发画像 → 单请求 token 吞吐 → 实测单卡吞吐 → 卡数 = 峰值吞吐 ÷ 单卡吞吐 × 冗余(1.3–1.5)
       ↑ 显存下限另算：权重 ÷ 单卡显存，两者取大
```

| 常量 | 值 | 一句话 |
|---|---|---|
| 冗余系数 | **1.3–1.5** | 拆三件：流量抖动 + 故障域容错 + 半年增长 |
| 内部助手活跃假设 | 日均 **10 轮/人**、峰值并发 **20–50**（500 人规模）、入 **2K** 出 **1K** token | 经典估算题的标准假设清单 |
| 72B / 500 人 结论 | **8–16 卡（80G 档）** | 假设清单比结论重要，结论给区间 |
| 320B MoE on 8×H20(141G) | TP=8，`--max-model-len 32768` 起步 | 640GB 地板；1M 标名单独压 |
| `--gpu-memory-utilization` | **0.9 起步** | 两端都是坑：太低 KV≈0 并发=1，太高挤掉 NCCL buffer 跑着 OOM |
| 上下文灰度 ramp | **32K → 128K → 1M（1M 单独压）** | 标称 ≠ 已验证 |

**判断线**：人头 ≠ 并发。2000 人内部助手，峰值并发在**几十**这个量级，不在 2000。

## 3. 引擎与生态速查

| 项 | 口径 |
|---|---|
| vLLM 快的两件事 | **PagedAttention**（KV 分页，消显存碎片 → 同显存容纳更多并发）+ **continuous batching**（请求级动态进出批） |
| PagedAttention 管的是什么 | **显存布局**，不是算子加速——被问"为什么快"别说"kernel 写得好" |
| continuous batching 保什么 | 提**吞吐**，不保**单请求延迟**；batch 越大 TPOT 越差，这是要业务签字的取舍 |
| SGLang 差异点 | **RadixAttention** 前缀树缓存（多轮/共享前缀命中率高）+ 结构化输出加速 |
| 新模型部署版本门槛来源 | 模型仓库**发布方的 release notes**（例：GLM-5.3-Flash 需 vLLM ≥ **0.28.0** / SGLang 最新版），不是"升级一下" |
| 投机解码风险 | 配置项跨版本改名 → **静默不生效**；必须看**接受率**，一次只开一项 |
| 引擎环境隔离 | torch / triton / flashinfer / xformers **会互相覆盖** → 每引擎一镜像/一 venv |
| 硬件边界 | 引擎生态决定硬件边界（CUDA-only；DSA/MTP 类特性可能 **Hopper-only**；V100 无 bf16）→ 三元组验证：模型 / 引擎版本 / GPU 架构 |

## 4. 并行与拓扑（TP/PP/EP/DP）

| 方式 | 切什么 | 通信发生地 | 显存 |
|---|---|---|---|
| **TP** | 层内（矩阵切列/行） | **每层** AllReduce → 必须 NVLink 域内 | 摊薄 |
| **PP** | 层间边界 | 只在层界点对点 → 可跨机 | 摊薄 |
| **EP** | 专家分布 | All-to-All（MoE 专属） | 摊薄专家 |
| **DP** | 副本 | 梯度同步（推理侧 = 多副本） | **不省单实例显存** |

**选择顺序**：节点内能 TP 就 TP → 放不下再跨机 PP/EP → 再要吞吐才 DP 加副本。
**拓扑感知三件事**：NVLink 域内优先、**gang scheduling** 防半批占卡死锁、网卡-GPU-NUMA 配对。
**gang 死锁经典形状**：两个 TP=8 任务各拿 4 张卡互相等。
现场命令：`nvidia-smi topo -m`（亲和矩阵）、`nccl-tests`（准入烤机）。

## 5. 量化 / 优化阶梯 / PD 分离

| 档位 | 显存 | 用途 | 必做 |
|---|---|---|---|
| **W8A8**（int8 权重+激活） | 约减半 | 通用首选，吞吐收益明确 | golden set 回归 |
| **W4A16**（AWQ/GPTQ） | 约 1/4 | "单卡放不下"的解法 | 精度评估最严 |
| **FP8 / 混合精度** | 中间档 | 精度极敏感场景 | 分任务指标 |

**优化阶梯（按性价比）**：前缀缓存 → 量化 → 连续批处理参数 → PD 分离 → 模型路由。
**前缀缓存**：重复系统提示词场景**立竿见影**；命中率靠"**把动态字段挪到提示词末尾**"（前缀必须逐字节一致）。
**PD 分离门槛**：prefill compute-bound / decode memory-bound，混部互相干扰；
**值得上的条件 = 大规模 + 长上下文 + 峰值明显**；代价 = KV 跨卡传输（IB/RDMA）+ 复杂度翻倍 + 故障域变大。
轻量替代：**chunked prefill**——规模不够时先想它。
**上限**：优化上限是硬件理论吞吐，报 MFU 对标（例：当前 MFU 12%，同类 H20 上 25% 是合理目标）。

## 6. 成本与稳定性口径

| 主题 | 口径 |
|---|---|
| **四本账**（TCO） | **资源 / 人力 / 隐性 / 风险**（题库口径；角色卡旧写法"算力/人力/数据/停机"不要混用） |
| 人力账 | 自建要养引擎+运维+SRE，通常**不低于卡成本**——最常漏算的一本 |
| 盈亏平衡 | 给"月调用量超过 X 亿 token 且数据必须留域内，私有化才回本"这条线 |
| 成本单位统一 | 全部换算成 **元/千 token** 或 **元/单次业务**，跨方案才能比 |
| 成本超 3 倍诊断 | 三张表：**利用率**（GPU 利用率 vs MFU）/ **请求分布**（长上下文占比、重复前缀占比）/ **批处理效率**（实际 batch、是否被上限卡住） |
| GPU 监控四件套 | **显存 / 算力利用率 / 延迟分位数 / XID 错误**，且**必须按卡打标签**（否则集群聚合曲线一定漂亮） |
| 利用率 vs MFU | **GPU 利用率只说"有 kernel 在跑"**，不说跑得好不好 → 看 MFU / 每卡 token 吞吐 |
| 慢节点三层发现 | ①延迟分位对比 ②ECC/降频 ③网络劣化（最容易误判成"卡坏了"） |
| 隔离验证闭环 | 摘掉嫌疑节点后**全场指标恢复**，才叫证明了归因 |
| NCCL hang 第一问 | **"是否所有 rank 到达同一个 collective"**——是→查链路/驱动；否→查某 rank 卡在自己的 CPU/IO 上 |
| 100 卡系统性防 | 准入体检（nccl-tests 烤机）/ 运行期自愈（XID 分级 + 页退役趋势告警）/ 版本**五元组**受控禁漂移 / 故障预算 |
| 多租户公平 | 三层配额（并发 + token/min + 日总量）+ **加权公平队列（WFQ）/ max-min（DRF）**；饿死本质是限流设计问题 |

## 7. SLA 与可用性换算（30 天 = 43200 分钟）

| SLO | 每月不可用 | 每年不可用 |
|---|---|---|
| 99.9% | **43.2 min** | 8.8 h |
| 99.95% | **21.6 min** | 4.4 h |
| 99.99% | **4.32 min** | 52.6 min |
| 99.999% | 25.9 s | **5.26 min** |

**推理侧 SLA 三段**：**TTFT**（首 token，受排队 + prefill 影响）/ **TPOT**（每输出 token，受 decode + batch 大小影响）/ **吞吐**（成本侧）。
三者互相拉扯：batch↑ → 吞吐↑、成本↓，但 TPOT↑（单请求变慢）——**这个取舍必须业务签字**，不能工程单方面定。
**依赖乘法**：串 3 个 99.9% 依赖 → 上限约 **99.7%**。
**burn rate 2% 规则**：短窗 1h 烧 2% 预算 → page；长窗 6h/3d 慢烧 → ticket。

## 9. 弱项口径（与 `简历/LLM-SRE.md` 一致，必须保持）

> **GPU/NCCL/Megatron 无生产经验，不吹。** 迁移性证据四件套：
> 大模型知识体系（两本书）+ 嵌入式驱动背景（硬件亲和）+ 网络排障功底（RDMA 可迁移）+ AI Stack 工单一手场景。
> **学习速度硬证据**：AI Stack 冷启动**两周** → **一周 50 单、闭环率 95%**。
> **补法三步**：跑通 vLLM benchmark → 读 PagedAttention 论文 → 复现一次量化回归。

**训练侧补课清单**（被问"你怎么补 gap"时报前 3 条）：
NCCL 集合通信与超时/hang 排查 → GPU 故障模式（XID/ECC/掉卡/MIG）→ RDMA/RoCE 无损网络（PFC/ECN、slow node）
→ Megatron TP/PP/DP/EP 与断点续训 → 训练可观测（loss spike / grad norm / MFU / straggler）→ 自愈（任务级重试/节点隔离/rank 级重启）。

**可现场演示资产**：故障树引擎（16 顶层事件 / 约 300 底事件）、73 个分析器、网络逐跳追踪。

**本域专属红线**：❌ **推理吞吐类数字没有"什么卡、什么配置、什么长度分布"三个限定** —— 这类数字一律不许出口。
