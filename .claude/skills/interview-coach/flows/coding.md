# Flow · 编码面试

> 适用岗位：所有工程师岗。AI 工程师考 prompt / 数据处理；SRE 考 Python/Go 工具开发。

## 总时长

30-45 分钟。**1-2 道题**。

## 阶段

### 1. 题目选择（2 分钟）
- 按 `../../knowledge/questions/<role>/` 选题（beginner / intermediate / senior 三档）
- 选完告诉用户题目，但**不**给思路提示

### 2. 需求澄清（3 分钟）
- 必问：
  - 输入 / 输出格式？边界值？空值？
  - 时间 / 空间复杂度要求？
  - 跑什么环境（纯函数？允许用 stdlib？）

> 工程师素养：能问出好问题，比直接动手强。

### 3. 思路（5 分钟）
- "你打算怎么解？先说思路，不要急着写代码"
- 用户说思路时，**不要打断**，听他讲完
- 听完如果有明显问题，**问**而不是"教"： "你刚才说用 hash，如果数据量是 1 亿呢？"

### 4. 编码（15-25 分钟）
- 让用户写代码（伪代码也行，但要能跑通逻辑）
- 边写边观察：命名、抽象、异常处理
- 用户卡住 → "你卡在哪？哪一步不确定？"
- 用户写得太啰嗦 → "这块能不能再简洁点？"

### 5. 测试（5 分钟）
- 写完必走：
  - "你打算怎么测？"
  - "给个边界用例"
  - "如果输入 null / 0 / 重复值，你现在的代码会怎样？"
- 让用户**自己**走一遍代码

### 6. 复盘（5 分钟）
- "时间复杂度？空间复杂度？"
- "有没有更优的解法？"
- "生产环境跑这段代码会出什么问题？"

### 7. 收尾
按 `../../SKILL.md` 的"收尾模板"出反馈。

## 评分维度

见 `../rubrics/coding.md`。

## 注意事项

- ❌ **不要**直接给最优解
- ❌ **不要**在用户没问的情况下提示
- ✅ 用户的命名、注释、错误处理都是考察点
- ✅ 编码风格反映工程师素养，**比 AC 更重要**
