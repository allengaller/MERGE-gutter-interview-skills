# Rubric · 编码评分

> 给 coding flow 用的评分维度。10 分制。

## 维度与权重

| 维度 | 权重 | 1-3 分 | 4-6 分 | 7-10 分 |
|------|------|--------|--------|---------|
| **问题理解** | 10% | 没问边界条件 | 问了 1-2 个 | 主动覆盖：null / 重复 / 极端值 |
| **思路清晰度** | 15% | 上来就写 | 思路基本清楚 | 数据结构 / 算法选择有解释 |
| **代码正确性** | 30% | 有明显 bug | 边界有 bug | 边界 + corner case 都处理 |
| **时间/空间复杂度** | 10% | 没分析 | 给了但不准 | 准确 + 给了优化空间 |
| **代码风格** | 15% | 命名混乱 / 无注释 | 命名尚可 | 命名有意义、有适当抽象 |
| **测试意识** | 10% | 没测 | 1-2 个用例 | 主动列测试矩阵 + edge case |
| **工程素养** | 10% | 没考虑异常 | 简单 try/except | 错误处理 + 日志 + 幂等 |

## 加分项

- ✅ 主动考虑线程安全 / 并发
- ✅ 主动考虑输入校验 / 防御性编程
- ✅ 写完后主动走读自己的代码
- ✅ 给出 Big-O 时考虑常数项
- ✅ 主动讨论空间换时间 / 预计算

## 减分项

- ❌ 抄板子没改（leet code 答案味儿）
- ❌ 不接受"换个解法"的追问
- ❌ 代码里 hardcode 数字 / 字符串
- ❌ 没用命名 / 抽象（一个 main 函数写到底）
- ❌ 异常直接吞掉

## 阈值参考

- **9-10**：Senior+ 工程师，code review 可以放手
- **7-8**：Senior 工程师，code review 偶有建议
- **5-6**：Mid 工程师，需要小 review
- **3-4**：Junior，需要 mentor
- **1-2**：基础不牢
