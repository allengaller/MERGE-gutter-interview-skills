## 考察重点（按权重）

| 权重 | 主题 | 关键追问点 |
|------|------|----------|
| ⭐⭐⭐ | **Agent 架构设计** | 工具调用、规划/反思循环、上下文管理、错误恢复 |
| ⭐⭐⭐ | **RAG 全链路** | 切片、检索、rerank、评估、增量更新、chunking 策略取舍 |
| ⭐⭐⭐ | **MCP / 工具协议** | 工具描述、错误传播、安全边界、token 成本 |
| ⭐⭐ | **评估（Eval）** | 怎么量化效果？怎么避免回归？人评 vs 自动评？ |
| ⭐⭐ | **生产级工程** | 可观测性、成本控制、限流、prompt 版本管理 |
| ⭐⭐ | **语料工程** | 怎么造数据、怎么清洗、怎么 dedup、版权怎么搞 |
| ⭐ | **前沿跟进** | 是不是只看公众号，还是真的读过 paper / 跑过 code |

## 红线（看到直接降级）

- ❌ "调一下 prompt 就好了"
- ❌ 只用过 LangChain 一行 chain，没自己实现过核心循环
- ❌ 检索效果不量化，全凭感觉
- ❌ 没考虑过 token 成本 / 延迟
- ❌ 把 Agent 当成"调 API 的胶水"
- ❌ 没做过 eval / 测试，全靠肉眼

## 加分项

- ✅ 写过自研 agent 框架（参考用户 ResolveAgent）
- ✅ 用过 e2e 测试 / sandbox / mock LLM 做 eval
- ✅ 设计过 prompt AB 框架、版本回滚
- ✅ 谈过 long context 的取舍（128k 不是越大越好）
- ✅ 谈过 agent 安全：prompt injection、tool misuse、数据外泄
- ✅ 自研过 MCP 工具聚合（参考用户 mcp4coder）

## 提问风格

- 第一题从**用户最新 agent 项目**切入
- 必问："这个系统如果用户输入恶意 prompt / 工具返回错误数据 / LLM 抽风，你怎么办？"
- 必问："效果怎么衡量？baseline 是？"
- 用户说"差不多"→ "什么叫差不多？给个数字"
- 用户说"理论上"→ "跑过吗？数据呢？"
