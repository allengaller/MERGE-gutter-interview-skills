# Agent 工程 SA · 专业轮题库（MaaS / Agent 方向）

> **目的**：验证"把 Agent/RAG 应用做成**客户敢上生产**的系统"的能力——线上最佳实践口径：评测驱动、护栏、灰度、成本闭环。
> **面试官**：MaaS/Agent 产品线资深专家。他天天看 demo，最反感"跑通了一次就说能用"。
> **专业轮 60 分钟**；HR / 高管 / 压力轮复用 [fullstack-sa](../fullstack-sa/README.md)，数字口径用本项目弹药卡。
> 深挖背景知识：[agent-architectures.md](../../topics/agent-architectures.md) / [rag-pipeline.md](../../topics/rag-pipeline.md) / [mcp.md](../../topics/mcp.md)。

## 面试官画像

见过太多"PPT Agent"和"一次跑通的 demo"。他要确认四件事：**评测体系在哪、护栏在哪、效果衰减了怎么办、成本怎么算**。答案里出现"golden set""灰度""审批分级""token 预算"这些词是加分信号。

## 方案面（客户场景 + 选型 + 设计）

### Q1 客户说"想用 Agent 提升运维效率"，你 30 分钟怎么澄清需求？一周怎么给出可演示的方案？
**追问**："如果他们的流程本身就没标准化呢？"
**参考要点**：澄清三件事——①目标流程与成功指标（MTTR/分流率）②数据与系统接口可得性（监控/日志/工单 API）③安全边界（哪些操作允许 Agent 自动做）。一周可演示 = 拿客户 1 个高频场景 + 脱敏数据跑通"诊断建议 + 人工确认"闭环。流程没标准化时先帮客户圈定 2-3 个标准化子流程切入，别试图全自动化。
**红线**：跳过澄清直接讲产品；承诺一周内全自动闭环。

### Q2 平台选型：百炼托管 Agent vs 开源框架自研（LangGraph/LangChain）vs 低代码平台（Dify 类），给客户的决策框架是什么？
**追问**："客户数据不能出内网呢？"
**参考要点**：决策四维——数据合规（出不出域）、团队能力（会不会写代码）、迭代速度、长期演进成本。默认建议：POC 用百炼/低代码快速验证，规模化看合规与定制深度决定是否私有化 + 开源自研。数据不出内网 → 私有化部署 + 开源模型，托管平台只做设计期参考。给客户的是"分期演进路径"而非单点选型。
**红线**：只推自己熟悉的一种；说不出三者迁移成本。

### Q3 多 Agent 编排 vs 单 Agent + 工具集，什么场景用哪个？线上代价是什么？
**追问**："客户坚持要'一个总控 Agent 调度多个专家 Agent'，你怎么劝？"
**参考要点**：线上最佳实践是**先单后多**——单 Agent + 好工具能解决 80% 场景；多 Agent 引入通信成本、误差累积、调试复杂度。真需要拆分：按"上下文隔离"（工具集太大 / 领域差异大）拆，不按组织架构拆。劝客户的方式：拿他的场景算两条路径的 token 成本与失败率，用数据说话；或先上单 Agent，预留编排演进位。
**红线**：把"多 Agent"当卖点堆架构图；说不出多 Agent 的调试成本。

### Q4 工具（function）设计：粒度怎么定？诊断树 vs 原子命令的取舍？
**追问**："工具报错时 Agent 怎么自我修复？"
**参考要点**：粒度折中——高频固定路径封装成粗粒度工具（省 token、稳），探索性场景给原子工具（灵活）。每个工具必须：幂等或可回滚、超时可控、**错误信息结构化可读**（Agent 拿到错误要能决策下一步），带清晰 description（Agent 选工具靠它）。生产做法：工具版本化管理 + 灰度上线 + 调用成功率监控。
**红线**：工具返回原始堆栈给模型；没有超时和重试语义。

### Q5 高危操作的护栏怎么设计？（Agent 要能执行变更/重启/工单操作）
**追问**："审批人不在，阻塞了业务怎么办？"
**参考要点**：分级护栏——只读自动放行、写操作审批、高危（删库/批量/外发）双人复核 + 白名单；执行侧沙箱隔离（容器/最小权限凭证，每 Agent 独立凭证、最小 RAM 权限）；全量审计日志（谁/何时/什么指令/什么结果），爆炸半径 = 权限 × 影响范围都要控。审批阻塞：分级超时升级（超时自动升级到上级 + 可配置自动放行的低危白名单），绝不默认放行高危。
**红线**："加个人工确认按钮"就算护栏；凭证全 Agent 共用。

### Q6 给客户的 Agent POC 怎么设计？跟全栈 SA 的 POC 差别在哪？
**追问**："准确率 92% 但客户说'不敢用'，怎么破？"
**参考要点**：POC 验证的是**业务指标 + 可信度**，不只是功能：golden 集上分层指标（任务成功率/幻觉率/平均 token 成本/时延）、badcase 展示与处理路径、护栏演示（故意触发高危操作被拦截）。"不敢用"的破法：人机协同优先（Agent 出诊断建议、人执行），用"采纳率"过渡指标积累信任，再逐步放权——这是业界上生产的标准节奏。
**红线**：成功标准只有"跑通"；演示不演护栏和失败场景。

## 技术面（深挖 + 动手）

### Q7 ReAct / Plan-Act-Reflect / Reflexion 各适合什么场景？线上你选哪个？
**追问**："Agent 死循环（反复调同一个工具）怎么办？"
**参考要点**：ReAct = 通用默认，简单可控；Plan-Act-Reflect 适合多步规划型任务（有可验证中间态）；Reflexion 类自我改进用于离线优化而非实时（成本高）。线上死循环治理：最大步数/最大 token 硬限制、重复动作检测（同参数同工具 N 次熔断）、循环模式进 prompt 反例、失败任务兜底转人工并记录。
**红线**：只会背论文名字说不出工程取舍；没考虑过循环失败模式。

### Q8 检索效果不好，怎么分层归因？golden dataset 怎么建？
**追问**："线上没有标注资源，怎么持续迭代？"
**参考要点**：先复现 → 隔离变量：检索侧（召回率/命中率/MRR）与生成侧（忠实度/相关性）分开评估，rerank 前后对比。golden set 从 badcase + 高频真实 query 起步（几百条就能迭代），标注口径写清楚。无标注资源：用线上采纳率/人工抽检做弱标注，badcase 自动入库，每周评测回归——评测集是资产，版本化管理。
**红线**："换个更大的模型"当第一反应；评测集从来不做版本管理。

### Q9 幻觉治理：给客户讲一套完整方案（不是"加了 RAG 就好"）
**追问**："医疗/金融客户要求 100% 无幻觉，你怎么回应？"
**参考要点**：三层缓解——输入层（检索增强 + query 改写）、推理层（证据链引用：答案必须挂来源、无来源即拒答）、输出层（置信度表达 + 拒答兜底 + 敏感词/合规过滤）。加上评测侧：幻觉率进指标、上线后采样人审。对 100% 诉求：诚实回应"做不到绝对，但可以做到**可验证**（每个结论可溯源）+ **有兜底**（拒答转人工）"，这本身就是专业度体现。
**红线**：承诺 0 幻觉；只答"用 RAG 就好了"。

### Q10 效果归因难题：一个回答错了，是语料缺失、检索失败还是模型推理错误？
**追问**："三种情况分别怎么修？"
**参考要点**：排查顺序固定化——①语料里有没有答案（有 → 检索问题；没有 → 语料/范围问题）②检索 top-k 里有没有相关文档（有但没用上 → rerank/排序问题）③证据对但答案错 → 模型推理/prompt 问题。修法：语料缺失 → 补文档/知识运营；检索失败 → 切分/同义词/rerank；推理错 → prompt 约束/换模型/微调。线上要做 trace（每步中间产物留痕）才能归因。
**红线**：凭感觉拍脑袋归因；不知道要留中间产物。

### Q11 上下文与 memory：长对话、多轮、跨会话怎么管？token 成本怎么控？
**追问**："系统提示词 5000 token，每轮都重发，怎么优化？"
**参考要点**：分层 memory——会话内（滑动窗口 + 摘要压缩）、用户级（画像/偏好，显式存储）、领域级（知识库走 RAG 而非塞上下文）。成本三招：**前缀缓存**（系统提示词/工具定义稳定前缀命中缓存，费用大降）、小模型路由（意图分类/格式化用小模型，主任务大模型）、工具结果截断与按需加载。线上要监控每会话 token 成本，设预算熔断。
**红线**：把全部历史无脑塞上下文；不知道前缀缓存这个机制。

### Q12 MCP 工具链：你真接过的经验？安全上要注意什么？
**追问**："接 37 个 MCP Server 的统一框架，踩过什么坑？"
**参考要点**：结合 mcp-database 实战讲——统一注册/发现/鉴权层，工具 schema 一致性，超时与降级统一处理。安全要点：MCP server 是**第三方代码，按供应链风险对待**（来源审计、最小权限、网络隔离、输出当不可信输入处理防注入）、凭证不进模型上下文、调用全审计。MCP 的价值在生态复用与解耦，代价是多一层运维与安全面。
**红线**：把 MCP server 输出直接信任；凭证硬编码在 server 里。

### Q13 Agent 上线后效果衰减（模型换了/知识更新了/用户行为变了），你的持续运营机制是什么？
**追问**："这套机制你真跑过吗？"
**参考要点**：评测驱动运营闭环——固定 golden set 回归（每次模型/prompt/工具变更必跑，防"改动打崩某类场景"）+ 线上采样评估 + badcase 自动回流（入库 → 归因 → 修复 → 回归验证）+ 指标看板（任务成功率/幻觉率/成本/时延四件套）+ 版本化发布（prompt/语料/模型都是版本，可回滚）。用 ResolveAgent 的真实迭代过程讲（准确率 85%+ 怎么一步步评出来、怎么防回归）。
**红线**："上线就结束了"没有运营；prompt 改动无回归直接全量。

## 本轮通过标准

- 每个方案都有评测体系与护栏设计，能说出线上失败模式（死循环/衰减/成本失控）及治理
- 上下文/成本/缓存有真实机制级理解（前缀缓存、模型路由）
- 归因方法论固定化、可复述；MCP 安全有供应链意识
- 全程区分"demo 能跑"和"生产敢用"——这就是这个岗位的价值
